# 2026-07-03 启动加速 + 后台更新检测

## 核心改动

### 1. License 验证去阻塞
- `verify_status` 不再调 `_get_stats()`（省 6s IP/地区查询）
- `init_trial` 三个调用点全部移除 `_get_stats()`
- FC 验证从同步改为子进程后台运行，不阻塞启动
- `verify_local` 先过（<1ms），RunLoop 秒启

### 2. 更新检测改子进程模式
- threading.Thread → subprocess.Popen（达芬奇不支持线程）
- sys.executable 通过 launcher 正确设置，无需硬编码
- 启动时 3s 轮询等结果 + _start_check 兜底读取
- stderr 捕获诊断崩溃原因

### 3. 更新按钮三态 UI
- ⏳ 检查更新中…（灰底灰字）
- ⬆ 更新（黄底黑字，有边框）
- ✓ 已是最新（灰底绿字）
- ⚠ 检查失败（灰底红字）

### 4. 错误文案规范
- MEMORY.md 新增铁律：用户可见文案必须是自然语言
- `osascript -128` → "更新已取消"
- 原始 stderr/系统错误码不在用户面前暴露

### 5. 边界处理
- 子进程崩溃 → stderr 诊断日志 + 不误报吊销
- 部分写入保护 → 读后必 os.remove
- 网络不通 → 静默降级
- FC 冷启动 10-15s → 子进程自己扛

## 已知遗留
- dd-mbp 是测试机（2.5.13），不应更新到 2.5.14
- 下载速度可优化（加国内 CDN 链路）
- 首次安装 `init_trial` 仍有一次 FC 冷启动（~10s），一次性
