## License v3 全链路调试（16:00-18:30）

### 核心修复

1. **urllib → curl 子进程**（`shared/license.py: _post_to_backend`）
   - 根因：DaVinci 子进程中 `urllib.request.urlopen` 的 SSL 上下文失败（`_create_unverified_context()` 在沙箱内不生效）
   - 方案：`subprocess.run(["curl", "-s", ...])` → curl 自带 SSL 栈，不受 Python SSL 限制
   - 修复后 FC 调用从 100% 失败 → 稳定连通

2. **sync 后 UI 重读凭证**（`交付自检工具/ui.py`）
   - 根因：`verify_local` 调 `_sync_trial_start` 把更新写入磁盘 → 但 UI 用的还是启动时 `load_credential()` 读到的旧内存副本，从未重读
   - 方案：`verify_local()` 返回后加一行 `cred = load_credential()`
   - 修复后改表首次启动即生效，不再等下一靴

3. **FC 日期序数时区对齐**（`cloud/license_fc.js: msToOrdinal`）
   - 根因：`Math.floor(ms / 86400000 + 719163)` 用 UTC 午夜算序数，飞书表存 UTC+8 → 差 1 天
   - 方案：`new Date(ms + 28800000)` 后用本地日期组件算序数（`getFullYear/getMonth/getDate` + 逐日累加）
   - 修复后 FC 返回序数与 Python `date.fromordinal()` 一致

4. **`init_trial` 路径日期计算统一**（`ui.py`）
   - 根因：试用路径用 `expire_time` 整数除 86400，受 `fromordinal().timestamp()` 时区偏移污染→差 1 天
   - 方案：统一用 `trial_start_date` 序数做 `30 - (today - fromordinal(tsd)).days`

5. **`save()` 防御性 str()**（`shared/secure_store.py`）
   - 根因：激活成功后将 `trial_remain_secs`（int）传入 `save()` → macOS keychain subprocess 崩溃
   - 方案：`save()` 入口 `value = str(value)`，任意类型安全

6. **pyc 缓存清除**（`交付自检工具/shell_personal.py`）
   - 根因：旧 `.pyc` 未清 → Python 优先加载过期字节码 → 修改不生效
   - 方案：launcher 启动前 `os.walk` 遍历 `__pycache__` → `shutil.rmtree`

### 保护机制

7. **未来日期拦截**：`_sync_trial_start` 中 `ordinal > today` → 拒绝更新，保留本地值
8. **离線宽限刷新**：每次 `verify_local` 成功 → `offline_grant_end = now + 3d`（不再从试用起始算）
9. **吊销 30 天宽限**：`verify_activation` 中 `_last_verify` 机制，FC 不通超 30 天才清凭据

### 经验教训

- **DaVinci 子进程不能走 Python SSL**：urllib 在沙箱内即使 `_create_unverified_context()` 也失败 → 用 curl 子进程彻底绕开
- **内存/磁盘不一致是隐蔽 bug 的主要来源**：sync 写了盘但 UI 不重读 → 追了 2 小时才定位到一行 `load_credential()` 缺失
- **日期运算远离浮点/整除**：序数减法是唯一可靠的方案，timestamp 整除 86400 被时区、闰秒污染
