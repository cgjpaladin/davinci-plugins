## 核心原则

- **决策来自时间线**：看片段名和颜色判断该做什么，不靠状态文件做决策
- **状态文件只存路径**：记录原片路径，供升级时查找
- **片段名即状态**：`_去字幕_快速预览_vXX` = 预览版，`_去字幕_正式出片_vXX` = 完成
- **零 pip**：仅 Python 标准库 + 达芬奇 API
- **跨平台**：`os.path.join`，macOS 零安装，Windows 多一步装 Python
- **主动提醒上下文**：当改动超过 8 次或会话超过 2 小时，主动建议写 memory + git commit + 暂停

## 交付结果

每轮处理完成后产出：

| # | 交付物 | 位置 | 说明 |
|---|--------|------|------|
| 1 | 去字幕.mp4 | `EP01/01_预览版/` 或 `02_正式出片/` | 处理后的视频文件 |
| 2 | 状态记录 | `.watermark_state.json` | 原片路径 + 当前路径 + 状态 |
| 3 | 操作日志 | `.ops_logs/op_{主机}_{日期}.jsonl` | 每次 API 调用的详细记录 |
| 4 | 并发锁 | `.locks/` | 运行时临时目录 |

## 输出文件命名


## 扫描逻辑（两种模式共用）

1. 扫 IO 区间内所有视频轨道
2. 去重：同名片段跨轨出现时，保留有标记颜色（默认橘色）的那轨
3. 过滤：只取标记颜色的片段，跳过无色的

## 快速预览流程

```
1. 扫描（见上） → 得标记片段列表
2. 对每个片段：
   ├─ 文件名含「正式出片」→ 打印 ✅ 跳过
   ├─ 文件名含「快速预览」→ 打印 ⏭ 跳过
   └─ 原片 → record_original → 调用 API → 下载到 01_预览版/ → ReplaceClip
3. 片段名变为：{原片}_去字幕_快速预览_vXX.mp4
4. 颜色状态：ReplaceClip 后标记颜色丢失（这是正常的）
```

## 正式出片流程

```
1. 扫描（见上） → 得标记片段列表
2. 额外扫描 → 取文件名含「快速预览」的片段（即使无颜色）→ 追加到列表
3. 对每个片段：
   ├─ 文件名含「正式出片」→ 打印 ✅ 跳过
   ├─ 文件名含「快速预览」→ 找原片（见下）→ ReplaceClip 还原 → 调用 API
   │                                 → 下载到 02_正式出片/ → ReplaceClip
   └─ 标记原片 → record_original → 调用 API（带 names + resolution=1080p）→ 下载到 02_正式出片/ → ReplaceClip
4. 片段名变为：{原片}_去字幕_正式出片_vXX.mp4
```

## 原片路径查找（正式出片时用）

找需要升级的片段的原片路径，决策树：

```
需要找原片（文件名含「快速预览」）
  │
  ├─ 1. need_restore(name, mode) 查状态文件
  │     └─ 找到 → 返回 original_path ✅
  │
  └─ 2. 状态无记录 → find 搜索 04_素材/02_视频/
        ├─ base = re.sub(r'_去字幕_.*$', '', name)
        ├─ find \"04_素材/02_视频/\" -name \"{base}.mp4\"
        ├─ 找到 → 返回路径 ✅
        └─ 找不到 → 打印 ⚠ 跳过
```

### find 实现

```python
import subprocess
base = re.sub(r'_去字幕_.*$', '', os.path.splitext(name)[0])
result = subprocess.run(
    ["find", "04_素材/02_视频/", "-name", f"{base}.mp4"],
    capture_output=True, text=True, cwd=project_root, timeout=10
)
orig = result.stdout.strip()
```

不猜 v0X/gridX 目录结构。SMB 上 1-2 秒可接受。

## 状态文件

```json
{
  "EP01_g1_01_v03.mp4": {
    "original_path": "/Volumes/.../02_视频/EP01/v03/grid1/EP01_g1_01_v03.mp4",
    "current_path": "/Volumes/.../03_去字幕/EP01/02_正式出片/EP01_g1_01_v03_去字幕_正式出片_v01.mp4",
    "status": "pro_box_done",
    "plugin_ver": "0.5",
    "last_updated": "2026-05-04 01:30:00"
  }
}
```

- key 为原片名（不含 _去字幕_ 后缀）
- original_path 永远指向 02_视频 下的源文件
- current_path 指向当前 ReplaceClip 后的文件
- status: original / basic_done / pro_box_done
- plugin_ver: 脚本版本号，方便追溯哪版脚本产生的记录

每次写入前自动备份：`.watermark_state.json` → `.watermark_state.json.bak`

## 并发安全

- 原子锁：`os.mkdir()` 在 SMB 上天然原子
- 锁文件：`.locks/{片段名}.lock/`（目录）
- TTL：10 分钟（`os.path.getmtime` 判断，处理耗时 40-70s + 3次重试 ≈ 3-4min，10min 有足够余量）
- 处理前抢锁，完成后释放

## 多用户并发

```
用户 A                      用户 B
选中 EP01_g1_01             选中 EP01_g1_01
点「开始」                   点「开始」
  ↓                          ↓
acquire_lock("EP01...")    acquire_lock("EP01...")
  → mkdir .locks/EP01...     → mkdir .locks/EP01...
  → 成功 ✅                   → FileExistsError ❌
  → 处理中...                 → 打印「⏭ 其他用户正在处理」
  → 完成，release_lock
```

- 不同片段互不影响，各自拿锁
- 相同片段只有先抢到锁的跑
- 锁 10 分钟自动过期，防止崩溃残留

## 异常处理

| 场景 | 行为 |
|------|------|
| IO 区间无标记颜色片段 | basic：报错退出。pro：继续检查升级片段 |
| 余额不足 | 打印 ⛔ 并退出，不处理任何片段 |
| 网络中断 | 重试 2 次，间隔 3/6 秒，全失败则跳过该片段 |
| 原片找不到 | 打印 ⚠ 跳过该片段 |
| ffprobe 拿不到时长 | 按 1 单位（30秒）兜底 | SMB 网络抖动、ffprobe 未安装或文件路径异常时可能发生 |
| ReplaceClip 失败 | 打印 ⚠，不更新状态 |
| 脚本异常崩溃 | lock 残留，10 分钟后自动过期 |
| API 返回失败 | 不扣点（鬼手失败免单），打印错误 |

## 停止机制

- **本地停止**（只停自己）：`/tmp/ai_subtitle.stop.{主机名}` — UI 点「停止」自动创建，或 Console 粘贴
- **全局停止**（停所有人）：`{PLUGIN_DIR}/.stop` — 总监在 SMB 上创建，紧急用。其他人不知晓、不操作
- 每个片段前两个都检查，停止后自动删除对应文件
- 当前片段跑完才停，不中断进行中的处理

## 部署流程

### Mac 部署（一键）

```bash
cd /Volumes/MYJC/06_Software/达芬奇脚本/AI去字幕
./deploy.sh
```

deploy.sh 做的事：
1. 检查 SMB 是否挂载
2. 复制 `AI去字幕.py` 到 `~/Library/.../Scripts/Edit/`
3. 删除旧版 `remove_watermark.py`

### Windows 部署（手动）

1. 安装 Python 3.10+（python.org 下载，一路下一步）
2. 挂载 SMB：映射网络驱动器 `\\192.168.1.154\MYJC` 到盘符 `Z:`
3. 复制启动器到 `%APPDATA%\Blackmagic Design\DaVinci Resolve\Fusion\Scripts\Edit\AI去字幕.py`
4. 启动器内容：`import sys; sys.path.insert(0, "Z:/06_Software/达芬奇脚本/AI去字幕"); from remove_watermark import main; main()`

### SMB 挂载要求

- 所有人统一挂载名：Mac = `/Volumes/MYJC`，Win = `Z:` 或网络路径
- 脚本代码在 SMB 上，总监更新后全员自动同步
- 每人本地只有一个启动器文件（5 行，永不更新）

## API Key 安全

### 当前方案

AppKey 和 AppSecret 默认从环境变量读取，兜底用 SMB config.py 里的硬编码值。

```python
GHOSTCUT_APP_KEY = os.environ.get("GHOSTCUT_APP_KEY", "硬编码兜底")
```

生产部署时，每人设 `GHOSTCUT_APP_KEY` + `GHOSTCUT_APP_SECRET` 环境变量，config.py 不写明文。

### 风险评估

| 风险 | 等级 | 说明 |
|------|------|------|
| 内网泄露 | 低 | 只在内网 SMB 上，需要 VPN |
| 剪辑师误操作 | 中 | 可能误开 config.py |
| API 被盗用 | 低 | 鬼手按点扣费，最多耗光余额 |

### 改进方向

- ~~config.py 隐藏~~（Finder 看不到但内容仍可读，不解决安全问题）
- 环境变量优先（已实现）→ 生产部署时撤掉硬编码兜底值即可

## 版本号规范

### 插件版本

`v0.5` → ... → `v1.0`

| 阶段 | 版本 | 含义 |
|------|------|------|
| 开发中 | v0.x | 功能不稳定，内部测试 |
| 自用成熟 | v1.0 | 自己团队跑通 |
| 对外发布 | v1.0+ | 给其他公司用 |

### 输出文件版本

`_v01`、`_v02`...

- 同一片段同模式跑多次，版本号自动递增
- 不覆盖已有文件
- 最高到 v99

### 文件名版本推导

```
EP01_g1_01_v03_去字幕_快速预览_v01.mp4
              ↑源版本             ↑输出版本
```

源版本（v03）是 Seedance 生成的版本号，和我们的输出版本号（v01）不同含义，不冲突。
