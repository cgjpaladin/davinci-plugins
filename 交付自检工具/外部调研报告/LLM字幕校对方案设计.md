# LLM 字幕校对 — 方案设计

> 2026-05-10 初版 | 2026-05-12 推翻：精确比对 → 语义校对 + 人物小传辅助

## 核心思路

**不是** 把 ASR 字幕和剧本逐行比对——实际拍摄中台词常被改、删、即兴发挥。
**而是** 利用剧本提供语义上下文（这场戏谁在说话、讲什么），让 LLM 判断 ASR 字幕里有没有不合理的错别字、人名错误、不通顺的地方。

## 信息源

| 来源 | 提取内容 | 作用 |
|------|---------|------|
| 剧本开头**人物小传** | 角色名单 `["林野", "顾曼曼", "苏冰颜", ...]` | 硬校验人名（林也→林野） |
| 当前集剧本 | 场景对话（EP07: 34 行） | 语义上下文 |
| 达芬奇字幕轨 | `GetName()` 取 ASR 文本 | 被校对的对象 |

## 常见错误类型

| 类型 | 例 |
|------|-----|
| 同音字 | 林野→林也、冰颜→冰言、保镖→保标 |
| 形近字 | 未→末、人→入、已→己 |
| 人名破碎 | 苏冰颜→苏冰盐、顾曼曼→顾慢慢 |
| 断句错 | 一条字幕塞了两个人的话 |
| 多字/重复 | 「求你了求你了」 |
| 缺语气词 | 「去死」vs「去死吧」 |
| 方言/口音误转 | 「这个」→「介个」 |

## 流程

```
达芬奇时间线
  ↓ GetName/GetStart/GetEnd
字幕文本 [{index, text}, ...]
  ↓
剧本 → 提取人物小传（角色名列表）
     → 提取当前集对话 → 语义上下文
  ↓ 分批（每批 20 条字幕）
LLM API（千问 Max / 豆包 Pro）
  Prompt: "已知角色: {names}
           当前集剧情: {context}
           检查以下 ASR 字幕是否有错别字/人名错误/不通顺"
  ↓ JSON 解析
[{index, asr, correct, reason}, ...]
  ↓ 组装 check_core 结果
Tree: ❌ 00:01:23:05 | 林也 → 林野 | 同音字
```

## 核心模块

### 1. 字幕读取
- 遍历字幕轨，取 `GetName()` 得到文本
- 记录时码、index

### 2. 剧本解析
- 飞书文档 → 拉取 docx → 提取纯文本
- 识别「人物简介」→ 提取角色名列表（正则 `^(.*?)（\d+岁）`）
- 识别「第N集」→ 提取当前集对话行

### 3. LLM 调用
- API：千问 Max（¥0.004/1K tok）或豆包 Pro
- 只用标准库 `urllib`，不引入 pip 依赖
- 每批 20 条 ASR 字幕 + 人物名列表 + 剧本上下文
- 要求 LLM 返回 `[{index, original, correction, reason}]` JSON
- 关键 prompt 约束：
  - 只看错别字和明显不合理的地方
  - 不要因为和剧本不一致就报错（剧组可能改过台词）
  - 人物名写错是最高优先级
  - 不确定的不报

### 4. 缓存
- 按字幕文本 hash 缓存，同一时间线重跑不花钱
- 存本地 `~/Library/Application Support/交付自检/typo_cache.json`
- 不跨机共享（防竞态）

### 5. check_core 集成
- `check_subtitle_typo()` 函数
- io_range 支持
- detail = `"{asr} → {correct}"`
- reason = `"{reason}"`
- CHECKS 注册：`"id": "typo", "section": "错别字校对", "group": "字幕"`

## API key 管理

- SMB `达芬奇脚本/shared/.env`，20 人共享
- `DASHSCOPE_API_KEY`（千问）或 `DOUBAO_API_KEY`（豆包）
