## 二、P0 级：阻断性问题

### 2.1 `ui.py` 2869 行 —— 单文件神级怪物

**问题**：UI 布局、配置弹窗、AI 校对（`_run_ai_typo` 含 157 行 `if not src:` 分支内置了 7 项独立检查）、一键更新（`_do_update` + `_do_update_sync` 共 ~300 行）、排错包导出、版本检查——全在一个文件。

**影响**：
- 任何一处改动都需要阅读 2800+ 行上下文
- 函数间隐式依赖全局变量 `_ai_allowed`、`_cred`、`_UPDATE_INFO`、`_UI_ERROR_COUNT`
- 无法独立测试配置弹窗或 AI 校对

**建议**：按职责拆分为 4 个文件：
- `ui.py` → 主窗口布局 + 检查触发 + Tree 渲染（~800 行）
- `ui_config.py` → 配置弹窗 + API Key 管理 + 激活/停用（~600 行）
- `ui_ai_typo.py` → AI 校对 + 系统规则预检（~500 行）
- `ui_update.py` → 一键更新（~300 行）
- `ui_export.py` → 排错包导出（~150 行）

### 2.2 `check_core.py` 1919 行 —— 检查逻辑单文件

**问题**：22 项检查全部在一个文件，导入 `camera_detect`/`deploy_config` 在文件底部（1477 行），违反 PEP 8。

**建议**：按模块拆分为：
- `check_core.py` → 缓存/工具函数（`_get_items`、`_get_smpte`、`_make_result`、`preload_timeline_items`）
- `checks/track.py` → 轨道结构/片段状态/越轨检测
- `checks/video.py` → 黑帧/黑边/变速/夹帧/直通编辑
- `checks/subtitle.py` → 字幕时长/换行/异体字/违禁词/全半角
- `checks/audio.py` → 声道/音频越轨
- `checks/color.py` → 调色/调色标记
- `checks/path.py` → 脱机/路径检测

### 2.3 在达芬奇内使用 `urllib` (ui.py:2476)

```python
from urllib.request import Request, urlopen   # line 2476
```

**严重性**：达芬奇子进程 SSL 沙箱限制，即使 `_create_unverified_context()` 也间歇失败。MEMORY.md 开发规则 #8 明确禁止。

**影响**：`_do_update_sync()` 中的下载逻辑使用 urllib，可能在某些机器/网络环境下 100% 失败。

**修复**：`_do_update_sync` 中的下载改用 `subprocess.run(["curl", ...])`，与 `llm_typo_check.py` 保持一致。

### 2.4 `_PRESET_HASH` 硬编码 Fairlight 预设 MD5 (check_core.py:263)

```python
_PRESET_HASH = "eb3ad5485026fa8e568608638d118a2d"
```

**问题**：预设文件更新后需要同时改代码。没有机制从 SMB 同步预设或从版本文件读取预期哈希。

**建议**：将预期哈希移到 `deploy.json` 或单独的 `fairlight_preset.hash` 文件，与预设文件同目录。

|------|------|:------:|
| `check_subtitle_clamping` | `_get_smpte(fps)` ✅ | — |

### 3.3 `for si in range(1, 2):` 硬编码仅检查 ST1

6 个函数中硬编码 `for si in range(1, 2):` 只检查第一条字幕轨：
- `check_subtitle_clamping` (line 330)
- `check_subtitle_glyph` (line 744)
- `check_subtitle_linebreak` (line 790)
- `check_subtitle_censor` (line 901)

**问题**：如果用户把字幕放到 ST2，这些检查全部失明。

**建议**：提取为 `_MAIN_SUBTITLE_TRACK = 1` 常量，或遍历所有字幕轨。

### 3.4 `_make_result_passthrough` 重复实现 (ui.py:483)

```python

    return {"status": status, "track": track, ...}
```

**问题**：两份相同代码，改一处忘一处 = 数据格式不一致。

**修复**：直接 `from check_core import _make_result`（已经是内部公开 API）。

### 3.5 `_run_censor_system` 和 `_run_censor_personal` 共享临时文件逻辑

两个函数（ui.py:372-481）都是：读 CSV → 写临时文件 → 调 `check_subtitle_censor` → 删临时文件。重复度 ~70%。

**建议**：提取 `_run_censor_from_csv(csv_path, ...)` 公共函数。

### 3.6 `_show_config_dialog` 函数体 ~400 行

包含：布局生成、控件初始化、激活/停用逻辑、SMB 路径编辑、违禁词编辑、API Key 保存。是整个 ui.py 中最复杂的函数。

**建议**：拆分为 `_build_config_layout()` / `_init_config_controls()` / `_bind_config_events()`。

### 3.7 配置弹窗中 `.env` 迁移逻辑每次打开都执行 (ui.py:1093-1119)

```python

    ...  # 每次都扫描 .env 文件
```

**问题**：迁移只需一次。如果 Keychain 已有 key，应跳过此步骤。

**修复**：在 `_load_api_keys()` 成功后设置标记，跳过重复迁移。

## 四、P2 级：中优先级

### 4.1 `except: pass` 裸异常吞没

```python
# ui.py:1131
except: pass
```

**位置**：`_show_config_dialog()` 的预填逻辑。如果控件未创建，所有后续配置字段也静默跳过。

**修复**：指定具体异常类型 + 记录日志。

### 4.2 `check_color` 函数中 issue 列表追加逻辑问题 (check_core.py:1350-1353)

```python
if tl_nodes > 0:
    issues.append(_make_result("fail", ...))  # 时间线有节点 = fail
# ...后面还可能添加片段节点问题
if not issues:
    return [_make_result("pass", ...)]  # ← 时间线节点问题忽略？
```

**问题**：时间线有节点时 `issues` 非空，不会走到 `return pass`。但如果 `GetNodeGraph` 抛异常 → `issues` 为空 → 返回 pass。

这不是 bug（时间线有节点确实应该报 fail），但逻辑流不够清晰。

### 4.3 同一时间线帧率被多次读取

`timeline.GetSetting("timelineFrameRate")` 在 `_start_check()` 中调了 1 次，但在 `_run_ai_typo()` 中调了 3 次，在多个 check 函数中各自调用。`fps` 参数已经传入，但在某些地方用 `project_fps`、某些用 `fps`，缺乏一致性。

### 4.4 `_collect_clip_files` 全量重建

每次 `check_path_location()` 和 `check_offline_clips()` 都会调 `_collect_clip_files()`，如果缓存为空则重建整个时间线的片段文件映射。I/O 密集。

**优化**：在 `preload_timeline_items` 阶段一起收集文件路径，存入 `_props_cache`。

### 4.5 `config.py` 中 SMB 路径常量已基本废弃但未清理
