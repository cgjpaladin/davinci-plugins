#### 77. rename vs archive 语义
重命名：os.rename(p, np) — 原位置改名，undo 可逆

→ 撤销只针对 rename，archive 后无法撤销

→ --onefile 会更大且每次全量打包

#### 79. bottle 随机端口
裁缝老师要求不写死端口 → socket 找空闲端口
→ 127.0.0.1:{random_port}，pywebview load_url
→ 轮询等待 bottle 就绪（最多 20 次 × 0.5s）

#### 80. _EMPTY_KEYS 设计
裁缝老师："我凭什么默认这个东西是 01"
→ ep/sc/gr/ver 初始为空，用户必须手动填
→ 不同于 author/method/status 可以有默认值
→ 影响：updButtons af 检查、状态栏缺失提示

#### 81. 键盘快捷键策略
裁缝老师要求纯鼠标操作，不加键盘快捷键
→ 例外：Enter（表单跳转）、Ctrl+Z（撤销）、Del（删除选中）、Cmd+A（全选）

#### 82. undo 栈设计
裁缝老师要求可撤销 → _undo_stack 是 list of lists
→ 每批 rename 一个 batch，undo 时 pop 整批
→ batch = [(old_path, new_path), ...]，undo 时 os.rename(new, old)

#### 83. 归档文件夹结构
裁缝老师要求简化归档路径
→ 原：root/EP/SC/EP_SC_GR_method_ver/filename
→ 改：root/EP/EP_SC_GR_method_ver/filename（去掉 SC 中间层）
→ build_folder 在 shared/naming.py

#### 84. getFields 的 desc 跳过逻辑
descCustomInput 和 descInput 并存时 → getFields 跳过 descInput，读 descCustomInput
→ descCustomInput 空值时也跳过（防止 _applyInspectorToSelected 误清）


## 第十轮 — 更多前端坑

#### 85. 事件监听器的 capture phase
裁缝老师发现数字验证在泛用 handler 之后运行 → 3 位数先写入再截断
→ 修：addEventListener('input', ..., true) 使用 capture phase 先于泛用 handler
→ stopImmediatePropagation() 阻止泛用 handler 重复执行

#### 86. inline style vs CSS 优先级
裁缝老师发现 SET 元素左边框不变色 → inline border-left 覆盖了 CSS border-color
→ 修：focus 时清除 inline border-left，让 CSS :focus 接管
→ blur 时恢复 inline border-left

#### 87. select 元素在 macOS 的渲染差异
裁缝老师发现 input 和 select 高度不一致 → macOS WebKit 下 select 有原生高度
→ 修：统一 height:26px + box-sizing:border-box

#### 88. toast 通知系统
裁缝老师需要操作反馈 → toast 函数 + CSS transition
→ 2500ms 自动消失，多次调用会取消前一个定时器
→ toast 内容为中文，位置固定在底部

#### 89. dialog 确认弹窗
裁缝老师需要危险操作前确认 → dialog overlay
→ Promise 模式：show → 等待用户点确认/取消 → resolve
→ 用于重命名/归档/撤销确认

#### 90. 文件列表点击事件复杂度
裁缝老师要求支持：单击选中、Cmd+单击多选、Shift+单击范围选
→ 已选中再点 = 不做事（防止 onMethodChange 副作用）
→ renderList 后 updButtons 再 _syncInspectorFromSelection

#### 91. CSS 变量在 pywebview 的兼容性
裁缝老师发现某些 CSS 变量在 WKWebView 不渲染
→ var(--green) 必须定义在 :root
→ 早期用硬编码颜色值备用
→ 最终全部走 CSS 变量

#### 92. 缩略图 background-image 回退
裁缝老师要求无缩略图时有占位色 → 渐变色 fallback
→ _thumbs[f.path] 存在 → url(data:...); 不存在 → linear-gradient

#### 93. empty state 设计
裁缝老师要求无文件时显示引导 → "拖放文件到此处 或 点击 +文件"
→ .fl-empty CSS 居中显示
→ 预览栏显示 "添加文件后显示预览"

#### 94. 泛用事件监听器重复绑定
裁缝老师发现某些事件被触发多次 → querySelectorAll + forEach 加到所有匹配元素
→ 需确保只绑定一次（不在 render 循环内绑定）
→ descInput/descSelect 重建元素时会丢失监听器


#### 95. pywebview DOMEventHandler 拖入路径
裁缝老师发现 macOS 拖入文件路径格式特殊 → 需要 DOMEventHandler + _process_paths
→ file:// 前缀 + 中文 URL encode → unquote 处理
→ 多文件拖入时 paths 数组直接传给 Python

#### 96. 缩略图生成与显示竞态
裁缝老师发现缩略图不是立刻显示 → generate_thumbnails 异步
→ JS 在 onDropResult 中先 renderList（无缩略图）→ loadThumbs 完成后再次 renderList

#### 97. readonly 和 disabled 的视觉区分
裁缝老师觉得 readonly（灰字）和 disabled（更灰+不可点）需要区分
→ readonly 用于自动计算字段（TK）和锁定字段（智能分镜 desc）
→ disabled 用于非选中状态的 SELECT（readOnly 对 select 无效）

#### 98. CSS 类选择器优先级冲突
.fl-item.sel 和 .fl-item.sel.rdy/.mis → 后者需更高优先级
→ .sel.rdy 必须定义在 .sel 之后
→ background 和 border-color 需要同时覆盖


## 第十一轮 — 系统性"拆东墙补西墙"模式

#### 99. 修一漏一模式（核心元问题）
裁缝老师："总感觉今天一直拆东墙补西墙，修一个漏一个"
→ 每次改完一个 bug，必然引入新的 bug 或忘改关联代码

#### 100. 关联改动遗漏清单
- 改 buildName → 漏 author（JS 和 Python 各漏各的）
- 加 method 到 build_filename → 忘更新 FILENAME_RE 正则 → parse 全死
- 改 background 替代 border-left → 5 个不同位置只改了 3 个
- 加 _lockInspector → 忘记它清背景会杀掉已填字段的绿色
- concat 替代 replace → 忘加路径去重
- 删检查按钮 → 连检查函数导入也删了
- 修一个 const 重复 → 同一次编辑引入另一个 const 重复
- replace_all "版本号" → "Version 版本号" 爆炸式扩散

#### 101. 根因分析
→ 改动影响面评估不足：改函数 A 时没想 B/C/D 谁调用了 A
→ 同类代码分散在多处：border-left 在 6 个不同函数里设
→ 测试不系统：只测了改动点，没测关联路径
→ 回滚不及时：发现问题后继续改而不是先恢复干净再重新来

#### 102. 预防措施
→ node --check 已进 build.sh（防 JS 语法错误）
→ 全局搜索：改任何函数/变量名，先 grep 搜所有引用
→ 三分支审计：if/elif/else 改完必须全验证
→ 小步 commit：每修一个独立 bug 就 commit，方便回滚


## 第十二轮 — 开发体验层面的坑

## 开发流程优化建议（综合性复盘）

#### 123. 开发/测试循环太慢
现状：改代码 → build.sh (30s+) → 打开 .app → 手动测试
→ 修复：(P1a 后) 做到浏览器 + mock API 完全等同于打包效果
→ mock 和真实 API 自动同步（name_format 已解决，还剩字段联动逻辑）

#### 124. 无自动化测试
现状：全靠裁缝老师手动点，每次改完赌"应该没问题"
→ 修复：至少加冒烟测试 — 拖入→填字段→全选→重命名→撤销（Python 脚本自动化）
→ 关键路径不变，只测一次，但每次改完跑一遍

#### 125. 错误不可见
现状：Python 异常在日志里，JS 错误沉默，用户看到的现象和根因差很远
→ 修复：Python 加全局异常钩子 → 弹 toast
→ JS 加 window.onerror → 弹 toast
→ 日志结构化（时间+来源+操作+结果）

#### 126. 状态管理复杂度过高
现状：inspector ↔ files[i].fields ↔ buildName 三向同步，手工维护
→ 修复（长期）：单 store 对象，observer 自动触发 render
→ 修复（短期）：_applyInspectorToSelected 只写真正变更的字段，不写全部

#### 127. 配置与代码混杂
现状：标签文字、颜色、placeholder 散落在 HTML/JS 多處
→ P1a 是第一步（UI 从 FIELD_CONFIG 生成）
→ 之后：颜色预设、字段验证规则、方法联动全进配置

#### 128. 浏览器预览不够真实
现状：mock API 返回假数据，和真实 Python API 行为差异大
→ 修复：mock 用和 Python 完全相同的 get_config 逻辑
→ 加 mock 模式时可拖入本地文件（File API + 本地路径）

#### 129. 代码审查缺失
现状：修完直接 build，没有 diff 审阅环节
→ 修复：build 前自动 git diff --stat，裁缝老师扫一眼再确认
→ 或者关键改动先 diff 再 build

#### 130. 文档/技能欠维护
现状：技能文件（批量命名工具开发）只在 session 结束时更新
→ 修复：每改完一个架构决策（如 P0/P1b）立刻更新技能
→ 技能当活文档用，不是事后补
