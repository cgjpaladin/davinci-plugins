## 代码审查维度（来源：code-review）

### 五维检查清单

| 维度 | 重点 | 优先级 |
|------|------|:--:|
| 安全 | 注入、认证、密钥、输入校验 | 🔴 |
| 性能 | 内存泄漏、N+1、缓存、异步 | 🔴 |
| 正确性 | 边界值、空值、竞态、时区 | 🔴 |
| 可维护性 | 命名、单责、死代码、魔法数 | 🟡 |
| 测试 | 边界覆盖、无 flaky、回归测试 | 🟡 |

### 三段式审阅流程

1. **第一遍（2-5分）：** 架构契合度、文件组织、方案选型
2. **第二遍（主力）：** 逐行逻辑、安全漏洞、性能、边界
3. **第三遍（5分）：** 生产故障模式、并发、回滚安全、遗漏测试

### 严重等级

| 等级 | 标签 | 阻断合并 |
|------|------|:--:|
| Critical | 安全漏洞/数据丢失/生产崩溃 | ✅ |
| Major | Bug/逻辑错误/性能回退 | ✅ |
| Minor | 可降低未来维护成本 | ❌ |
| Nit | 风格偏好/命名建议 | ❌ |

## 调试协议（来源：debug-pro）

### 七步法

1. **复现** — 稳定触发，记录步骤/输入/环境
2. **隔离** — 缩小范围，注释代码，`git bisect`
3. **假设** — 形成可测试的根因猜想
4. **插桩** — 加日志/断点/断言
5. **验证** — 确认根因，假设错了回第 3 步
6. **修复** — 最小正确修复，不要边 debug 边重构
7. **回归测试** — 写一个能捕获此 bug 的测试

### Python 专用

```bash
python -m pdb script.py
breakpoint()          # Python 3.7+
python -m cProfile -s cumulative script.py
```

### 网络诊断速查

```bash
curl -v https://api.example.com/endpoint
curl -w "@curl-format.txt" -o /dev/null -s https://example.com
lsof -i :PORT
```

## 工作流设计模式（来源：n8n-workflow-automation）

> 以下模式从 n8n JSON 提炼，适用于任何自动化/管线系统。

### 幂等性
- 定义去重键 → 每次运行前查存储 → 跳过已处理
- 重试不产生重复记录

### 可观测性
- 每次运行生成 `run_id`
- 记录开始/结束时间 + 各阶段状态
- 失败写完整上下文（输入 + 错误栈）

### 错误处理
- 每步独立的错误分支（不靠全局 try/except）
- 重试 + 指数退避
- 最终失败通知（不是无声挂死）

### 人工审核队列（HITL）
- 失败项写入队列（Sheet/DB）
- 需人工确认后重新处理
- "无声失败"门禁：计数/阈值不过 → 停工作流 + 告警

### 适用场景
- 我们的 pipeline_base → 已有部分实现，缺 HITL 和无失败告警
- 达芬奇脚本灰度发布 → 可借鉴幂等性和审计

## UI 交互参考（来源：ui-ux-design）

> 以下从 Web/Mobile UI 提炼，适用于批量命名工具（pywebview HTML 前端）。

### 视觉层级
- **尺寸** 越大越重要
- **颜色** 亮/对比 = 吸引注意力
- **留白** 越多 = 强调越强
- **间距** 8px 倍数体系（8, 16, 24, 32, 48, 64）

### 色彩系统
- Primary → 品牌色（按钮/链接/激活态）
- Neutral → 灰度 50-900（文字/背景/边框）
- Semantic → 成功绿/错误红/警告橙黄

### 可访问性（WCAG 2.2）
- 文字对比度最低 4.5:1
- 大文字（18px+）最低 3:1
- 颜色不能是唯一的区分方式（加图标/文字）
